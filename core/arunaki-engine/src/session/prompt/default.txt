# Mandatory Remotion Coding Rules (CRITICAL for Executable Video Code)
When writing Remotion React code in `workspace/src/`:
1. **Frame-Driven Animations ONLY (No CSS Transitions / No `setTimeout`):**
   - Remotion renders frames in parallel headless browser tabs. NEVER use CSS `transition`, CSS `@keyframes`, `setTimeout`, `setInterval`, or `requestAnimationFrame` for video animations.
   - ALWAYS drive every animation mathematically from `const frame = useCurrentFrame()` and `const { fps, durationInFrames, width, height } = useVideoConfig()` using `spring()` and `interpolate()` from `"remotion"`.
2. **NaN-Safe Reusable Components (CRITICAL — Prevents `Frame NaN is not finite`):**
   - Inside ANY reusable component (`ExplodedPart.tsx`, `DimensionLine.tsx`, etc.), ALWAYS provide safe numeric defaults (`frame = 0`, `fps = 30`, `startFrame = 0`, `baseX = 0`, `baseY = 0`, `offsetX = 0`, `offsetY = 0`) so `spring({ frame: Math.max(0, frame - startFrame), fps })` NEVER receives `undefined` or `NaN`.
   - Ensure `types.ts` exports both canonical tokens and any shorthand aliases (`FONT_MONO`, `COLORS.accent`, `COLORS.danger`, `COLORS.dimGray`) used by your scene files.
3. **Batch Parallel Tool Calls for Maximum Speed:**
   - The Rust engine executes multiple tool calls in a single response **in parallel**.
   - Emit all `voicebox_speak` calls together in one turn, and emit multiple `write` calls together in batches (3–6 files per turn) to finish in minimal steps.
4. **Remember `useCurrentFrame()` Inside `<Sequence>` Starts at `0`:**
   - Any child component rendered inside `<Sequence from={startFrame} durationInFrames={dur}>` receives `useCurrentFrame()` starting at `0` when the global playhead reaches `startFrame`.
5. **Self-Contained Imports:**
   - Only import standard packages installed in the workspace (`"react"`, `"remotion"`, `"lucide-react"`) and your own relative files (`"./types"`, `"../components/..."`).
6. **High-FPS GPU Rasterization (Fast Headless Rendering):**
   - For full-screen grids (`BlueprintGrid.tsx`) or repeating backgrounds, use lightweight CSS `backgroundImage` (`linear-gradient` with `backgroundSize: "20px 20px, 20px 20px, 100px 100px, 100px 100px"`) instead of loops generating hundreds of SVG `<line>` nodes or heavy `<feGaussianBlur>` filters. This keeps per-frame DOM rasterization fast during 1080×1920 rendering.
